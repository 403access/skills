01 — Method

No survey. No guesswork.
Just the database.

OpenCode keeps every message, tool call, token and compaction in a local SQLite file. I read it read-only, separated mine from the agent's, and tagged 3,784 human prompts with 34 signals.

Extract, read-only

761 sessions and 82,283 events from session_v2 and session_message. The V2 store is a strict superset of the legacy mirror, verified by row counts and ID overlap.

Separate the voices

274 sessions are subagents spawned by the agent itself. Their “prompts” are machine-written, so every stylistic statistic uses only the 487 root sessions / 3,784 human prompts.

Tag every prompt

Length, structure, paths, acceptance language, constraints, dangling pronouns, commit rituals, corrections, payload size. Conservative regex — the rules are published so they can be audited.

Measure what came back

Turns to finish, rework (≥2 corrections), compaction events, tool-error classes, tokens, duration. Four outcome proxies, each with its confounders stated.

Turn it into skills

Each finding became an agent skill, the skills were installed, and the whole pipeline — extract → analyse → publish — is committed and reproducible.

# the entire study is three deterministic steps
$ node scripts/extract.mjs   # local DB → data/ (gitignored)
$ node scripts/analyze.mjs   # data/ → analysis/report.json
$ node scripts/build-site.mjs # report.json → this site

02 — Findings

The prompt was never the problem.
The missing artifact was.

Finding 01 14.9%

One in six prompts is bookkeeping.

565 prompts were “stage and commit relevant changes”, restart requests or “did you commit?”. They appear in 261 of 487 sessions. In one project, a third of all prompts are housekeeping.

Finding 02 47.5%

The chat is the state store.

Almost half of all prompts are under 60 characters. Median session: 3 prompts. But the mean is 7.8 and 17.9% of sessions cross ten prompts — that tail is where state gets lost.

Finding 03 46%

Context loss is a failure mode.

In the largest project, 30 of 65 sessions compacted the context window (83 events). The top tool error — 38% of all errors — is editing a file whose contents the model no longer has right.

Finding 04 2×

Structure halves the loop.

Sessions whose first prompt has a list average 4.3 prompts; without one, 8.6. Constraints: 4.7 vs 9.0. Acceptance language doesn’t shorten sessions — it halves rework, 4.7% vs 7.8%.

Finding 05 80.5%

“Done” was never defined.

Four in five prompts had no acceptance criteria. Verification arrived later as “did you test…?” — including the classic lint task “solved” with eslint-disable, which had to be rejected.

Finding 06 1.0%

The model was not the bottleneck.

91,061 tool calls, 940 errors — and most are mechanical: stale anchors, interrupts, no-op edits. Switching models was never the fix. The request was.

signal frequency

Structure and constraints are the rarest signals — and the two that correlate most strongly with short sessions.

03 — Output

Seven skills,
each tied to a number.

These are not prompt tips. They are SKILL.md packages the agent loads when the situation appears — a brief before an edit, evidence before “done”, a checkpoint before the context dies.

prompt-brief

Write the brief before the first edit.

Goal, scope, constraints, acceptance, verification, out of scope. For multi-file or irreversible work — and a fast path for one-liners.

read → done-evidence

“Done” means verified.

Build, typecheck, lint, tests, runtime check. No suppression comments. A fixed evidence block that names what was not verified.

read → commit-hygiene

Committing is a policy, not a prompt.

Only touched files, conventional message, checks first, hash + file list back. Never amend or push unless asked.

read → context-packet

Point at artifacts, don’t paste them.

Data path, why, relevant lines, question, budget. Keeps the instruction larger than the log.

read → change-scope

Keep the diff inside the request.

No drive-by refactors, no new dependencies, no formatting of untouched files, no speculative abstractions. Stop conditions included.

read → ui-change-loop

Visual changes need a baseline.

Viewport matrix, one concern per change, before/after evidence, dark mode and reduced motion as acceptance.

read → session-checkpoint

Long sessions decay. Checkpoint them.

Ten lines: state, decisions, files, verification, next, open questions. Resume cold instead of summarising a 90-turn thread.

read → guide

How the set fits together.

Which skill triggers when, what each one removes, and the install command. Plus the project-instruction snippet that makes it all stick.

04 — What I got wrong

Three beliefs the data killed.

“Never paste big context.”

Sessions that start with a large payload finish in 2.8 prompts instead of 8.9. Dumps work for one-shot extraction jobs. The problem is using them for conversations.

“Short prompts are lazy.”

Terse first prompts average 5.2 prompts per session vs 8.2. Brevity is fine for one observable change. Ambiguity is the enemy, not length.

“A better model fixes it.”

1.0% tool-error rate across 20 models. 62% of those errors are stale edit anchors or user interrupts. The bottleneck is specification and state, not reasoning.

Caveat, stated plainly: this is one person, 29 projects, heuristic labels and uncontrolled comparisons. The direction is consistent across five large projects; the effect sizes are not causal. Read the findings with confidence levels →
